# 请求详情记录

入口：**系统设置 → 网关服务 → 请求详情记录**。与系统运行日志、实时请求查看分别管理。

- 新安装默认关闭，开启后写入 `/app/data/request-details/request-details.jsonl`。标准 Docker 部署已持久化 `/app/data`，不需要另加日志目录挂载。
- 未保存面板配置时，继续使用 `SUB2API_REQUEST_DETAIL_LOG_PATH`、`SUB2API_REQUEST_DETAIL_LOG_MODE`、`SUB2API_REQUEST_DETAIL_LOG_BODY_LIMIT_KB`、`SUB2API_REQUEST_DETAIL_LOG_SOURCE`。
- 首次保存后，记录开关、模式、正文上限和来源标识由数据库中的面板设置管理，并保存当前路径。之后移除旧环境变量也不会丢失已保存的路径。
- 路径在面板中只读。启动时选择顺序：显式 `SUB2API_REQUEST_DETAIL_LOG_PATH` → 数据库保存的路径 → `/app/data/request-details/request-details.jsonl`。如需迁移到不同目录，用环境变量指定新路径并重启，再在面板保存；不会自动搬运旧文件。
- 旧部署仍须保留该路径对应的目录挂载，以及外部日志采集器配置。数据库备份不包含日志文件；仅更换 Docker 镜像也不会自动迁移数据库或数据卷。

保存后当前实例立即应用，其他实例每 5 秒读取一次数据库。每个实例保留自己的启动路径；数据库短暂不可用时保留上次生效的策略，不阻塞业务请求。

启动时无法读取记录配置，不影响网关启动：暂不启用文件记录，在面板提示错误并后台重试。首次成功读取前拒绝保存，避免覆盖尚未读到的原配置；恢复后仍使用原来保存的路径。

关闭记录会停止新增文件日志，已经进入写入队列的记录会继续写完，不删除历史文件，也不关闭实时查看。模式和大小变更不追溯补采正在处理的请求正文。

`raw` 保存原始请求；`dual` 额外提取对话；`structured` 仅在 Responses 请求成功提取对话且 HTTP 状态为 2xx/3xx 时省略原文，其他情况保留原文。正文上限为 256 或 512 KB。日志可能包含用户对话内容，按需开启。

沿用原有轮转策略：单文件 100 MB、最多 2 个备份、备份保留 1 天并压缩。写入使用有界队列，不阻塞业务；队列满和磁盘写入失败时，面板显示本次运行累计数量。点击“重新加载”查看最新状态。目录不可写时不会把“配置已启用”误报成“文件记录已启用”。
